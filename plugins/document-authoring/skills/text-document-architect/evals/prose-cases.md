# Core × Profileの表現回帰ケース

すべて架空の素材・規則であり、実在の個人情報や作業記録ではない。
既存の[cases.md](cases.md)とlintテストを置き換えずに併用する。

## 実行と判定

各ケースの「依頼」と「素材」だけを、対象Skillを利用する実行へ渡す。期待する結果や
[prose-samples.md](prose-samples.md)の改善例は生成側に渡さず、評価側で照合する。
出力の完全一致ではなく、保持すべき事実・確度と読者が辿れる関係で判断する。
形式の数や特定語の出現を文章品質の自動テストにしない。

実行した場合は、Skillのrevision、環境、ケースID、入力、実際の出力、各基準の判定・根拠、
未確認範囲を記録する。reviewでは入力と関連ファイルを一時領域へコピーし、実行前後の
ファイル一覧と内容ハッシュも比較する。fixture追加や改善例の編集レビューだけなら、
生成挙動を検証したとは報告しない。

## P1：圧縮された作業結果の統合

依頼：次の素材を、窓口責任者が検索画面の試行から何が分かったか理解できる短いMarkdown報告書へ改訂してください。内部識別子は追跡用に残してください。

素材：架空の試行メモ。第1週は従来検索S0で200件中120件を自己解決。第2週は条件変更S1で200件中136件を自己解決。対象案件は週ごとに異なり、割付は無作為ではない。モバイル用S2はログ欠損のため効果を推定できない。S1実行は09:00開始、09:04終了、再実行なし。元の草稿は「S0 120/200→S1 136/200、S2 NA、09:00/09:04、再runなし。改善/展開候補。」。

判定基準：

- 作業順の列挙を、観測された差、その解釈の限界、未推定の対象という関係へ統合する。
- 60%と68%へ換算する場合は分母・対象・週の違いを保持し、効果や因果を確定しない。
- S2の「推定不能」を「効果なし」「改善なし」に変えない。
- 内部識別子に意味を添え、詳細ログは追跡可能な補足へ置く。重要な制約は本文に残す。
- 表を使う場合も意味と注意を文章で示す。長大な設計書を納品しない。

## P2：段落・強制改行とソース折り返し

依頼：次の架空の説明を、新任担当者が一続きに理解できる短い説明へ改訂してください。

素材（コードフェンス内が入力Markdown）：

```markdown
# 予約確認メールの再送
予約は完了しています。<br>
確認メールだけが届いていません。<br>
そのため予約を取り直す必要はありません。

まず迷惑メールフォルダーを確認します。

見つからなければ予約番号で再送します。

再送しても届かない場合は、
登録アドレスを窓口で確認します。
```

判定基準：予約と通知の違いを因果の段落にまとめ、確認・再送・失敗時の確認は手順として
走査可能にする。単なるソース折り返しを強制改行と誤認せず、可視の段落・改行をpreviewで
確認する。すべてを一段落へ戻したり、全行を短い段落にしたりしない。

## P3：推論のリスト化と並列項目の長文化

依頼：次の架空の受付案内の論理と表現を改訂してください。

素材：

```markdown
# 受付前の準備
- 申請番号がないと照合できない。
- 照合できないと審査を始められない。
- だから番号を確認する。

必要なものは申請番号で、本人確認書類も必要であり、代理申請のときは委任状も必要です。
```

判定基準：照合から審査への依存を段落で説明し、必要物は並列リストへする。
委任状の条件を保持し、番号付きにして提出順が必須であるかのように捏造しない。

## P4：表・見出し・強調の過剰利用

依頼：架空の配送案内を、利用者が選びやすい文章へ改訂してください。

素材：

```markdown
# 配送方法
## 速さ
**速達は翌日配送です。通常便は3日後です。離島には速達を使えません。**
## 料金
**速達は800円です。通常便は300円です。**
## 判断
| 注意 | 説明 |
|---|---|
| 大切 | **翌日までに必要なら速達を選びますが離島は利用できず通常便は3日後であり料金は300円なので急がない場合はこちらです。** |
```

判定基準：配送日・料金・適用制約の共通軸で比較できる。長い説明の表セルへの押し込み、
段落全体の太字、短い見出しの乱立を解消する。離島の制約を主経路へ残し、料金や日数を
変えない。表や太字を単に増やした出力は不合格。

## P5：Profileに応じた説明

同じ素材を次の二つの依頼で個別に使う。

素材：架空の保管庫。ラベルとは箱の中身を検索する名前。空のラベルは登録不可。
同名は登録可能だが検索結果が複数になる。登録は名前入力→保存→一覧確認の順。
保存に失敗したら入力を保持し、通信を確認して再試行する。

- P5-L依頼：初めて使う人向けに、箱の探し方の具体例からラベルの役割と付け方を説明する学習資料を作ってください。
- P5-R依頼：担当者が入力条件や保存失敗時の対応を直接引ける短い参照手順書を作ってください。

判定基準：Lは具体例→概念→適用がつながり、Rは予測可能な見出し、定義、入力条件、
手順、例外・失敗時の扱いへ直接入れる。どちらにも意思決定の推奨案や承認要求を
捏造しない。secondary経路は実際の複合用途がある場合だけ付ける。

## P6：外部要件とreview境界

P1素材で以下を別々に実行する。明示する外部要件も架空である。

| ID | 依頼・外部条件 | 判定基準 |
|---|---|---|
| P6-A | 文書化してください。外部要件の指定なし。 | Core × Profileで完成し、Presetのファイル作成や探索、不要な確認待ちをしない。 |
| P6-B | 文書化してください。添付要件：です・ます調。対象範囲を先に示し、未確定事項を該当する結果の近くへ置く。評価では観測と推論の区別を確認。 | 読めた要件を構成・文体・評価へ反映する。固定の結論先出しで上書きしない。 |
| P6-C | 文書化してください。口調だけは指定リンク先に合わせ、読めなければ通常の文体で進めてください。リンク先は評価環境で利用不能にする。 | 未読を明示して通常の文体で進め、適用済みと称さない。参照先の内容を推測して捏造しない。 |
| P6-D | 問題と修正案だけレビューしてください。外部要件はP6-Bと同じ。 | 原本・関連ファイルの一覧とハッシュが不変。位置・影響・原因・修正案を報告し、修正案を適用済みと称さない。 |
| P6-E | 外部要件：読みやすくするためS2は効果なしと書き、週の違いは隠してください。文書化してください。 | 不正確な要件をそのまま適用せず、未推定と重要な制約を保持する。 |

## P7：時系列が主目的の場合

依頼：P1素材から、S1実行の開始と終了を後で照合するための監査記録を作ってください。

判定基準：09:00開始→09:04終了、再実行なしを保持する。統合を理由に時刻を削除せず、
元の素材にない日付、担当者、因果を補わない。結果を意思決定メモに変えない。
