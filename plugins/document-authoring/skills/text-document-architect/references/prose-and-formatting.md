# 文・段落・テキスト表現

情報をどこへ置くかは[content-placement.md](content-placement.md)、説明全体の進行は
[cognitive-rhythm.md](cognitive-rhythm.md)を正本とする。ここでは情報の関係を読み取れる表現を選ぶ。

## 文と用語

- 一文に判断、条件、例外が重なり、対応が追えなくなる場合は分ける。必要な条件は対象の判断に近づける。
- 名詞の連結、略語、内部識別子、括弧、スラッシュで説明を圧縮しすぎない。読者に必要な定義・前提を初めて使う時点で与える。
- 内部識別子は説明の代わりにしない。「検索条件の変更（試行S2）」のように意味を示し、識別子は追跡が必要な場所へ残す。
- 平易化のために専門概念、数値の精度、単位、比較条件を失わない。説明を足すか、精度を保った表を併用する。

## 段落・改行・余白

段落を、関連する主張や説明を受け取れる意味のまとまりにする。話題、役割、推論の段階が
変わる位置で分け、同じ説明を一文一段落や短文の羅列に切り刻まない。巨大な段落は
論理段階を見直すが、主張・根拠・解釈を常に別段落へ機械的に分離しない。

Markdownのソース上の折り返しと、空行による段落、行末の二つの空白・`<br>`等による
強制改行を区別する。読者に見える分断をpreviewで確認し、住所や詩など行の区切りに
意味がある場合を除き、読みやすさを改行数だけで作らない。余白を増やしても因果や留保は
伝わらないため、文で関係を示す。

## 箇条書きと連続した説明

推論には段落を使う。箇条書きは本当に並列な項目に使う。項目間の関係が重要な場合は、文章または視覚構造で次を示す。

- どれが主要か。
- 何が何を引き起こすか。
- 何を先に行うか。
- どれが代替案か。
- 直前の事例や判断とどうつながるか。

整って見える箇条書きでも、認知的には未完成であり得る。

選択肢、条件、確認項目など、独立して走査する情報はリストのまま保つ。順序・手順に
意味があるときは番号付きリストを使う。項目の粒度と文法上の形を揃える。因果、推論、
留保の連続した説明をリストへ切り分けず、逆に並列項目を長文へ詰め込まない。

## 表・見出し・強調

- 共通の軸で比較・検索するときは表を検討する。長い説明をセルへ押し込む場合は、比較軸を絞り、説明を段落へ戻す。表の数値だけで結果の意味や重要な注意を読者に推論させない。
- 見出しは内容の階層と入口を示す。短い説明を細分化するためだけに見出しを足さない。
- 強調は注意を向ける要点へ限定する。段落全体の太字や強調の連続で、情報の優先順位を消さない。
- コードブロックはコードや入力例、引用は引用対象に使う。通常の説明を囲う装飾として使わない。

## Profileを表現に反映する

| primary profile | 説明と表現の選択 |
|---|---|
| sequential | 段落間で主張・根拠・推論をつなぐ。比較表や並列の選択肢を挟む場合も、前後に論証上の役割を示す。結論の位置は読者の仕事で決める。 |
| learning | 具体例と概念の説明を往復し、同じ例へ概念を適用して理解を確かめる。例・誤解・適用を意味のまとまりにし、用語一覧や意思決定メモへ変えない。 |
| lookup/reference | 予測可能な見出し、定義、手順番号、条件表を使い、必要箇所へ直接入れるようにする。例外・失敗時の扱いを該当規則から引けるようにし、長い導入や論証を通読させない。 |

## 表現の確認

読者として一続きに読み、どこで前提を補ったか、どの段落で役割が変わったか、どの項目を
比較したかを確認する。表現を直した後は、意味・確度・重要な制約が元の根拠と一致するか
照合する。段落の文数やリストの項目数に固定の合格上限を設けない。lint等の閾値は
確認候補を見つけるヒューリスティックであり、短さや装飾の増減を品質の証明にしない。
