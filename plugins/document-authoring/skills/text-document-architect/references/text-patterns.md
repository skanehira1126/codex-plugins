# 読者の仕事別テキスト文書パターン

読者が文書を使って何をするかでパターンを選ぶ。役割を持たない要素は省く。

## 意思決定メモ・役員向け事前配布

1. 求める判断と推奨案
2. なぜ今その判断が必要か
3. 決定的な根拠と診断
4. 選択肢、評価基準、トレードオフ
5. 推奨案と、代替案が劣る理由
6. リスク、可逆性、責任者、時期、評価指標

結論を先に出す。通常、開いたままにする問いは「推奨案は何か」ではなく、「なぜこの推奨案が妥当か」である。

## 提案書・推奨書

1. 読者が認識できる現在の結果・摩擦
2. 分かりやすい説明だけでは足りない理由
3. 根本原因または拘束条件
4. 有効な対応に必要な設計原則
5. 提案する介入と作用機序
6. 根拠、反論、境界、試行方法
7. 求める判断または次の行動

読者が問題定義を評価できる前に、解決策を押し出さない。

## 分析・調査報告書

1. 調査の問いと範囲
2. データ、方法、重要な限界
3. 重要度順の発見
4. 解釈と代替説明
5. 対象判断・領域への含意
6. 残る不確実性と次に必要な根拠

発見を長く並べた後に遠く離れた考察を置くのではなく、発見、根拠、解釈、含意を適切な単位で往復させる。

## 解説記事・学習資料

1. 身近な経験、異常、実務上の困りごと
2. 読者が答えを必要とする具体的な問い
3. 具体的な事例・観察
4. 有用な説明として導入する概念・モデル
5. 仕組みと適用範囲
6. 二つ目の事例への適用
7. モデルの再構成と次の利用

読者が参照用途で使う場合を除き、「辞書的定義 → 説明」より「問題 → 概念の必要性 → 定義」を優先する。

## 業務手順書・規程・仕様書・参照文書

1. 適用範囲と対象利用者
2. 定義と全体マップ
3. 作業順の規則・手順
4. 条件分岐、判断、例外
5. 例と失敗時の扱い
6. 責任、統制、更新履歴

予測可能なナビゲーションと引き当てやすさを優先する。物語的なサスペンスを作らない。

## 進捗報告

1. 目的と現在地
2. 前回からの重要な変化
3. 根拠とマイルストーンの動き
4. リスク、阻害要因、責任者
5. 必要な判断・支援
6. 次の確認時点

変わらない背景を繰り返さない。差分、影響、必要な介入を中心にする。
