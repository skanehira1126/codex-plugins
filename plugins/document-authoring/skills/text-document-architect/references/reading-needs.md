# 読み方に応じて考慮すること

文書種別ごとの必須テンプレートではない。読者が実際にどう使うかに応じて、必要な
工夫だけを選ぶ。主な読み方を一つ決め、複合用途がある場合だけ補助の参照経路を加える。
作成・レビューなどの動作モードとは別に考える。

## 順に読んで理解・判断する（sequential）

読者が、前の説明を使って次を理解できる順序を考える。発見や主張を並べるだけでなく、
その根拠、解釈、含意を近くで結ぶ。比較表や選択肢のリストを挟む場合も、それが何を
判断するためのものかを前後の文章で示す。

意思決定が求められるなら、求める判断や推奨を早めに示すと読みやすい。一方、問題の
捉え方を共有する必要があるなら、具体的な現象から説明を組み立ててもよい。
結論先出しをすべての用途に強制せず、人工的なサスペンスで必要な情報を遅らせない。

複数の結果をまとめる場合、差が示す意味と代替説明を見比べる。経過の共有であれば、
前回からの変化とその影響を中心にし、背景を毎回繰り返さない。

## 事例から理解を身につける（learning）

具体的な経験や問いから、概念が役立つ場面を示すと理解しやすい。概念を説明した後は
同じ事例や別の事例へ適用し、どこまで使えるか、何を誤解しやすいかを確かめる。
定義の一覧だけにも、意思決定を求める論証だけにもしない。

説明が続いて読者の理解を確かめられない場合は、比較、短い例、適用上の問いを検討する。
例を増やすこと自体を目的にせず、読者が概念と具体を結び付けられるものを選ぶ。

## 必要な情報を引いて使う（lookup/reference）

予測可能な見出しと用語、定義、作業順の手順、条件・例外の一覧が役立つ。
本文を最初から読まなくても、該当箇所から適用範囲、入力、分岐、結果、失敗時の扱いを
確認できるかを試す。例外は対象の規則から参照できるようにする。

長い説明は必要な箇所から読めるようにし、物語的な導入や結論型見出しを無理に付けない。
学習と参照の両方が必要なら、学習の流れを保ちながら用語・例外を引く入口を設ける。
