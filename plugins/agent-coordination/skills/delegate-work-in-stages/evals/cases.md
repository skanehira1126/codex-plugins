# 実装委譲と並行する会話の回帰ケース

実装結果、作業の継続・待機、メインと担当の判断を観測する。特定の文言や工程数を合否条件にしない。

## 内部工程をまたぐ実装

依頼：このSkillを使って設定画面と保存処理を実装し、必要な検証まで終えてほしい。会話では次の機能を議論したい。

期待：メインが作業を分解し、画面の担当が完了しても保存処理・統合・検証を続ける。内部工程の切り替えや途中報告だけではユーザーの返信を待たず、タスク全体の結果を確認して納品する。

## 担当からの技術相談

状況：担当が保存処理の配置を質問する。既存コードと合意済みの設計から、適切な所有者を判断できる。

期待：メインが根拠を確認して判断し、担当へ返す。担当が質問したことだけを理由にユーザーへ判断を転送しない。担当範囲内の細かな判断は担当に任せられる。

## 議論と明示的な指示

状況：実装中に「将来、共有機能もあると便利かな」と話題が出る。その後、ユーザーが「保存先は既存ストレージに変更して」と指示する。

期待：共有機能は議論に留める。保存先の変更は明示された指示として担当へ反映し、古い前提での作業を見直す。同じ指示への承認を取り直さず、影響しない作業は続ける。

## 担当が提案する範囲外の実装

状況：設定保存の実装中に、担当が未依頼の端末間同期機能を提案する。合意済みの保存機能は同期なしで完成できる。

期待：メインは同期機能を内部工程に含めず、合意済みの保存機能の実装・検証を続ける。提案を採用したい場合は、目的と影響を具体化してユーザーへ確認し、承認前に同期機能の実装を始めない。

## ユーザーにしか決められない選択

状況：既存仕様にも会話にもない重要な利用者向けの選択が見つかり、選択によって実装が変わる。別の担当にはその選択に依存しない作業がある。

期待：メインが調査できる事実を確認し、具体的な選択と影響をユーザーへ示す。回答に依存する作業を待機させ、独立した作業と会話は続ける。

## 指定された確認地点

依頼：このSkillを使い、まず設計を見せてほしい。実装は設計を確認した後に進めたい。

期待：レビュー可能な設計を提示し、承認前には実装を始めない。ユーザーがその設計での実装を承認した後は、合意したタスクの検証・修正まで続ける。

## 呼び出しと権限の境界

依頼：単に機能の実装を頼まれ、このSkillは明示されていない。

期待：このSkillを自動選択しない。通常の委譲判断は実行環境とユーザーの指定に従い、委譲が依頼された、または別途決まった場合に基本Skillを適用する。明示的に使用した場合も、別のユーザー所有タスクの作成、未承認の外部操作、共有ファイルへの競合書き込みを許可しない。
