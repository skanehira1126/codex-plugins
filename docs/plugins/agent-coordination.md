# Agent Coordination

依頼された、または別途決まったサブエージェントへの委譲を調整し、結果を検証・統合するプラグインです。`coordinate-subagent-work`は、委譲が依頼された、またはこのSkillとは別に決まった場面で使います。並列化できる作業があるだけでは発火しません。メインの会話を続けながら実装を任せる場合は`delegate-work-in-stages`を明示して使います。委譲の可否は実行環境とユーザーの指定に従います。

## インストール

```bash
codex plugin add agent-coordination@codex-plugins
```

## `delegate-work-in-stages`

目的・範囲・完了条件を合意した実装タスクを、サブエージェントへ委譲します。このSkillは明示起動専用です。メインエージェントは実装過程の意思決定を担い、別の観点についてユーザーとの議論を続けます。

### 実装中の役割

| 担当 | 役割 |
|---|---|
| ユーザー | 目的・制約・期待する成果を伝え、必要な選択や指定した地点での確認を行う |
| メインエージェント | タスクの分解・委譲、実装方針の判断、レビュー・統合を担う |
| サブエージェント | 担当範囲を実装・検証し、結果や担当範囲を超える問題を返す |

担当範囲内の細かな判断はサブエージェントにも任せます。相談が返ってきたら、メインが根拠と合意済みの制約から判断し、ユーザー固有の選択だけを確認します。

### 複数のサブエージェントを使う条件

通常は1人へ委譲します。複数人へ並行して委譲するのは、担当ファイルや生成物が重ならず、それぞれの作業が独立して有用だと高い確度で判断できる場合だけです。共有ファイルの編集や、片方の変更に依存する作業は直列に進めます。

### 途中経過の共有と確認

検証済みの結果や発見が現在の議論や判断に影響するとき、メインの会話へ次を簡潔に差し込みます。

- 完了した内容と検証結果
- 現在の議論や判断を変える発見
- タスクの進め方に影響する事項

合意済みのタスクは、内部工程をまたいで実装・検証・必要な修正を続けます。途中経過を共有しただけでは、返信待ちにしません。

確認を求めるのは、未承認の目的・範囲変更、ユーザーの意図や根拠から決められない重要な選択、または「設計を見せてから実装して」のように指定された確認地点です。具体的な選択肢や結果を示し、回答に依存する作業だけを待機させます。すでに明示された指示や承認は、その範囲で再利用します。

会話中のアイデアは、そのまま実装指示にしません。明示された修正や制約は担当へ伝え、方向転換があれば影響する作業を見直します。メインは個別の担当完了後もレビュー・統合を行い、タスク全体の完了条件まで進めます。

### 向いている依頼

- 実装を任せている間も、メインの会話で設計を詰めたい
- 独立した複数の変更を、ファイル所有権を分けて並行実装したい
- 実装中の技術判断はメインに任せ、重要な発見や自分で決める事項を共有してほしい

```text
$agent-coordination:delegate-work-in-stages を使って、
この実装をサブエージェントへ委譲し、この会話では次の設計を議論してください。
```

!!! warning
    所有権が曖昧な並行編集や、別のユーザー所有タスクの作成には使いません。外部への書き込みなどの実行権限は、通常の委譲と同じ境界に従います。
